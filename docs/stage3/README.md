# Stage 3 — Vertical Slice: What Was Built, Verified, and Deferred

Status: **complete, awaiting review**. First code in the repo, per the approved Stage 2
architecture and DR-1…DR-10.

## What exists

**Backend** (`server/`, Python 3.15 / FastAPI / SQLAlchemy / SQLite / content-addressed
object store in `var/`):
- Auth (scrypt, session cookies), projects, members/roles, private-by-default (404 to
  non-members), append-only activity events.
- Dataset ingest: CSV parse, unit detection from headers, content hash, immutable raw
  bytes, unknowns flagged (undeclared units, missing license) — never defaulted.
- Tool contract framework: Pydantic contracts with unit-aware input validation via
  astropy.units; violations rejected naming the constraint, never clamped.
- Two registered tools: `stellar.wien_temperature` and `stellar.blackbody_fit`
  (scale-normalised Planck fit with statistical uncertainty, convergence/physical-range
  checks, peak-outside-window warning). Constants via the CODATA facade only.
- Run orchestrator: subprocess worker pool (DR-4) with wall-clock timeout and
  pool-rebuild on kill; environment versions captured inside the worker that computed
  the result. Full run provenance per c-schemas §3; failed runs persist with logs.
- Notebook: heading/text/figure blocks; figure blocks reference run@version (no copied
  values); per-block optimistic concurrency — a stale write returns 409 with the server
  copy and applies nothing (I-8).
- Reports: assembled from saved artifacts only; export freezes an artifact@version +
  sha256 manifest; re-export creates a new version, old versions byte-stable; dataset
  unknowns and run warnings land in the limitations section; guards render with figures.
- Alembic configured with an initial autogenerated revision (`server/migrations/`).

**Frontend** (`frontend/`, React/TS/Vite/Plotly): login, projects, project overview
(members, datasets, workbench, runs, notebooks, reports, activity), dataset view with
plot + unknowns, tool page generated from the contract (unit selectors, dataset binding,
guards, checks, result plot, insert-into-notebook), run detail (full provenance), notebook
(edit with conflict UX), report versions. Dark glass theme per the Stage 1 tokens.

**Sample data**: synthetic 5772 K spectrum with absorption features and seeded noise
(`sample_data/`, CC0, generator script, provenance label `simulated`).

## How it was verified

- **17 automated tests pass** (`server/tests/`, pytest):
  - P-1 physics: Wien identity (rtol 1e-12), solar peak, Planck integral vs
    Stefan–Boltzmann (rtol 1e-6), numeric peak vs analytic (rtol 1e-8), fit recovery of
    a known temperature within its own uncertainty across seeds, nm/Å/m unit
    equivalence, guard presence, validation rejection cases.
  - Constants policy: AST scan — no hand-typed high-precision literals outside the
    facade; facade values equal scipy.constants.
  - API slice: privacy/roles/audit (A-1), ingest+hash+unknowns (A-2/3), full run
    provenance, determinism, immutability of prior runs, canonical-unit recording,
    retrievable arrays (A-4/5), rejection-not-clamping, notebook reference semantics +
    409 conflict + cross-project reference block (A-10), report manifest freezing +
    limitations + version stability (A-11), Wien end-to-end.
- **Frontend**: `tsc` + production build clean; full spine walked manually in the
  browser against live servers — register → project → upload sample spectrum → blackbody
  fit (T_eff = 5760 ± 4 K on the 5772 K synthetic; the ~3σ offset is the real
  line-blanketing bias the tool's caveats describe) → figure into notebook → report
  created → v1 exported with a 2-artifact frozen manifest verified by hash.

## Known limitations (honest list)

1. **HTML export only**; PDF via Playwright print lands in Stage 4 (DR-9 unchanged).
   Exported HTML loads Plotly from a CDN, so figures need network to display.
2. **No memory caps on workers** (Windows gap); wall-clock timeout only. Revisit with
   Job Objects or when the hosted worker service is built.
3. Run execution is synchronous in-request — correct for `instant` tools, and the
   `long-running` path (queue + status + cancel UI) is still unbuilt.
4. No comments, variants/branching UI, comparison view, presence, or code cells yet —
   Stage 4/5 scope per §15. `parent_run` exists in the schema and API.
5. Sample dataset is synthetic (labelled as such everywhere); a real public-archive
   spectrum with recorded license is Stage 4 (D6).
6. Schema is created by `create_all` at startup; Alembic is initialised and stamped, and
   owns every schema change from here on.
7. Plotly makes the JS bundle ~4.9 MB (DR-7's accepted cost); partial bundles later.
8. Dev accounts are local-only; the seed account lives in `server/scripts/dev_seed.json`.

## Running it

```
.venv\Scripts\python.exe -m uvicorn lattice.app:app --port 8000 --app-dir server
npm run dev --prefix frontend     # http://localhost:5173, proxies /api to 8000
cd server && ..\.venv\Scripts\python.exe -m pytest tests -q
```
